# Работа с AOP: Thaumcraft 4

## Область проекта

Это исходники неофициального порта Thaumcraft 4.2.3.5 с Minecraft 1.7.10 на Minecraft 1.21.1 / NeoForge. Рабочий корень - эта папка `repo`, а не её родительская папка с архивами и отчётами.

- `api/src/main` - публичный API; `api/src/test` - проверки правил.
- `mod/src/main/java/thaumcraft` - игровая реализация.
- `mod/src/main/resources` - ресурсы и игровые данные; `mod/src/main/templates` - метаданные.
- `mod/src/productionVerification`, `mod/src/verification`, `mod/src/smoke` - отдельные проверочные source sets. Они нужны и должны оставаться в репозитории, но не в игровом JAR.
- Оригинальный JAR, внешние порты, скрипты извлечения, исторические отчёты, кэши и миры находятся вне репозитория. Не добавляй их в Git.

## Правила взаимодействия

- Работай самостоятельно без субагентов, пока пользователь явно не попросит их использовать.
- Перед неоговорённым продуктовым или архитектурным выбором спроси пользователя. Уже принятые решения повторно не согласовывай.
- Перед удалением пользовательских данных, изменением существующих миров или иным необратимым действием получи подтверждение.
- Не выполняй глобальный поиск по всему проекту, когда область задачи известна. Сначала выбери нужный модуль или каталог и используй `rg` в этой области.
- Перед поиском или сканированием всего проекта получи подтверждение пользователя. Если пользователь назвал конкретный файл, ограничь изменения этим файлом.
- Не перечитывай целиком уже прочитанные файлы без необходимости; для уточнения используй нужный фрагмент.
- На Windows используй PowerShell. Не запускай `CMD.exe` или `.bat` без явного разрешения пользователя; для Gradle есть `gradlew.ps1`.
- Не запускай Impeccable и `cargo fmt`. Не форматируй посторонние файлы ради текущей задачи.
- Не создавай worktree без запроса. Если он нужен по просьбе пользователя, размещай его в `<корень репозитория>/.worktree/`.
- Не создавай коммиты, не меняй существующую историю и не публикуй код без соответствующего запроса пользователя.

## Сборка

Нужен JDK 21. Версии Minecraft, NeoForge, Curios и самого порта определены в `gradle.properties`; Gradle - в `gradle/wrapper/gradle-wrapper.properties`. Не обновляй их попутно.

Из корня репозитория, в PowerShell:

```powershell
.\gradlew.ps1 build
.\gradlew.ps1 :mod:runClient
.\gradlew.ps1 :mod:runServer
```

`gradlew.ps1` ищет Java в локальной `.tools/java21`, затем в родительской `.tools/java21`, `JAVA_HOME` и `PATH`. При наличии родительского кэша Gradle он может использовать его; установку JDK и кэши не коммить.

Игровой JAR создаётся в `mod/build/libs/`. API включён в него; отдельный `api/build/libs/` предназначен для разработчиков дополнений. Curios обязателен, TerraBlender необязателен. Интеграция TerraBlender и резервный Mixin размещения биомов должны оставаться взаимоисключающими.

## Изменения механик

- Ориентир - поведение Thaumcraft 4.2.3.5. Не заменяй исходные значения, последовательность случайных вызовов, радиусы, рецепты или геометрию на более удобные без согласования.
- Не выдавай существование класса или успешную компиляцию за подтверждение правильной работы механики.
- Сохраняй совместимость NBT, SavedData, attachments и компонентов предметов. Не исправляй проблему удалением сохранений.
- Изменения мира, инвентарей и расхода ресурсов должны оставаться под контролем серверного потока. Клиент отвечает за отображение и ввод.
- Не добавляй блокирующее ожидание генерации чанков на серверном тике. Подготовка портала и естественной генерации выполняется постепенно, с сохранением исходных радиусов и геометрии.
- Проверяй отмену задач, удаление целей, выгрузку чанков, перезапуск мира и освобождение принадлежащих задаче tickets, если изменение затрагивает эти пути.

### Принятые решения пользователя

- Пустотная мантия имеет фиксированный фиолетовый цвет `#6A3880`. Рецепта её окрашивания быть не должно; обычная мантия остаётся окрашиваемой.
- Оригинальная перегонка сохраняет интервалы 40 тиков и 20 тиков с алументумом.
- Анимации HUD имеют одинаковую длительность при 30/60/144 FPS с сохранением вида при 60 FPS.
- Настройка бура палочкой направляет его противоположно вектору взгляда игрока; направление не должно зависеть от случайно выбранной грани блока.
- Удалённый банк эссенции не должен задерживать использование других действительных источников инфузии.
- Отладочные игровые проверки оставлены в репозитории по решению пользователя.

## Проверка результата

- Запускай проверки, соответствующие изменению. Для документации не требуется повторная игровая регрессия; проверь команды, пути и ссылки.
- Обычный `build` проверяет компиляцию и правила API/эссенции, но не заменяет игровые проверки.
- Серверные сценарии запускаются, например, через `.\gradlew.ps1 :mod:runR3Server -Pr3Phase=production`. Выбирай фазу по изменённой системе и её обработчику в проверочном коде, а не по догадке.
- Игровые сценарии изменяют мир. Используй отдельные тестовые профили из `runs/`, не пользовательские сохранения. Не меняй EULA без принятия пользователем.
- Для сцен с сохранением и перезапуском сначала подготовь предусмотренную сценарием исходную фикстуру. Не используй остатки другого теста как доказательство.
- Проверяй фактический `passed` в свежем JSON-протоколе, ошибки сервера и код завершения процесса. Указывай, какие проверки действительно выполнены.
- Для изменений рендеринга сборка сама по себе недостаточна. Проверяй реальный клиент и необходимые направления, состояния, прозрачность, тени и длительность анимаций. Не подменяй игровую проверку браузером.
- Проверочный код, миры, логи и отчёты не должны попадать в игровой JAR. Сопоставляй проверенный код с выдаваемым артефактом.
