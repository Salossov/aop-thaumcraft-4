# Книга, исследования и данные

[К оглавлению](README.ru.md) | [Быстрый старт](QUICKSTART.ru.md) | [Java API](API.ru.md) | [English](CONTENT.en.md)

Справочник описывает форматы категорий книги, исследований, страниц, аспектов и рецептов. Пути приводятся относительно каталога ресурсов дополнения `src/main/resources`. Датапаки используют ту же структуру `data/`; новые определения аспектов и особых типов страниц требуют установленного Java-дополнения.

## Файлы и идентификаторы

| Содержимое | Путь |
| --- | --- |
| Категория, исследование, страница, назначения аспектов | `data/myaddon/thaumcraft/<любое_имя>.json` |
| Рецепт Minecraft/Thaumcraft | `data/myaddon/recipe/<имя>.json` |
| Переводы | `assets/myaddon/lang/ru_ru.json`, `en_us.json` |
| Иконка аспекта | `assets/myaddon/textures/aspects/<имя>.png` |

Для 1.21.1 каталог рецептов называется **`recipe`**, в единственном числе. Каждый файл в `thaumcraft/` - один объект с полем `kind`; вложенные каталоги разрешены. Рецепты используют `type` и лежат отдельно. Не кладите туда произвольные конфиги JSON: неизвестный `kind` прерывает загрузку.

Новые ключи имеют пространство имён, например `myaddon:introduction`. Ключи книги ограничены 128 символами. Старые ключи ядра (`THAUMONOMICON`, `GOGGLES`, `ROD_greatwood`) сохраняют регистр и прежнее написание. ID рецепта получается из пути: `data/myaddon/recipe/diamond.json` → `myaddon:diamond`.

У категории и страницы `id` можно опустить: будет использован ID файла относительно `thaumcraft/`. Для ясности в примерах он указан явно. Исследование требует собственного поля `key`.

## Категория

`data/myaddon/thaumcraft/workshop.json`:

```json
{
  "kind": "book_category",
  "id": "myaddon:workshop",
  "name": "category.myaddon.workshop",
  "icon": "minecraft:textures/item/diamond.png",
  "background": "thaumcraft:textures/gui/gui_researchback.png",
  "order": 100,
  "required_research": ""
}
```

`name` - ключ перевода; `icon` и `background` - пути PNG, включая `textures/` и расширение. `order` по умолчанию 100; категории сортируются по нему, затем по ID. `required_research` по умолчанию пуст: иначе вкладка показывается после завершения указанного исследования. Исследование должно существовать, и зависимость не должна делать вкладку недостижимой.

Java-эквивалент: `AddonRegistry.category(new BookCategory(id, name, icon, background, order, requiredResearch))` в событии регистрации. Не регистрируйте эту же категорию ещё и в JSON.

## Исследование

`data/myaddon/thaumcraft/introduction.json`:

```json
{
  "kind": "research",
  "key": "myaddon:introduction",
  "category": "myaddon:workshop",
  "parents": ["THAUMONOMICON"],
  "auto_unlock": true,
  "column": 0,
  "row": 0,
  "icon": "minecraft:diamond",
  "text_pages": [],
  "recipe_pages": ["myaddon:diamond"],
  "page_order": ["myaddon:introduction_page", "myaddon:diamond"]
}
```

Этот вводный пример выдаётся автоматически. `auto_unlock` выдаёт исследование при обработке автоматических знаний; не рассчитывайте, что он проверит родителей. Для обычного изучаемого исследования поставьте `false` и, например, задайте `aspects: {"aer": 1, "ordo": 1}`, `complexity: 1`.

| Поле | Тип / значение по умолчанию | Назначение |
| --- | --- | --- |
| `key`, `category`, `icon` | Обязательные строки | Постоянный ключ, ID категории и иконка предмета |
| `parents`, `hidden_parents` | Массив строк / `[]` | Все эти исследования требуются для доступности; вторые - скрытые зависимости |
| `aspects` | Объект / `{}` | Аспекты исследования: положительные целые 1–32767 |
| `complexity` | Целое / `0` | Сложность 0–3 |
| `column`, `row` | Целые / `0` | Положение узла на карте исследований, не пиксели страницы |
| `auto_unlock` | Boolean / `false` | Автоматическое завершение при обработке автоматических знаний |
| `hidden` | Boolean / `false` | Скрытая ветка с отдельным состоянием обнаружения |
| `concealed`, `virtual`, `round`, `stub`, `secondary`, `special` | Boolean / `false` | Флаги TC4; `virtual` исключает обычный узел из карты/доступности, `round`/`special` меняют оформление. Не заменяют серверную проверку знаний |
| `siblings` | Массив строк / `[]` | Связанные исследования; все ссылки должны существовать |
| `warp` | Целое / `0` | Искажение 0–127 |
| `text_pages`, `recipe_pages` | Массив строк / `[]` | Ключи старых текстовых страниц и ID рецептов |
| `page_order` | Массив строк | Явный порядок текстов, рецептов, групп рецептов и новых `book_page` |
| `recipe_groups` | Объект / `{}` | Имя страницы → непустой массив вариантов из `recipe_pages` |
| `page_requirements` | Объект / `{}` | Ключ страницы → исследование, требуемое для показа этой страницы |
| `item_triggers`, `entity_triggers`, `aspect_triggers` | Массив строк / `[]` | Условия обнаружения скрытых исследований через сканирование |
| `required_item_tags` | Массив строк / `[]` | Фильтр загрузки исследования по наличию предметов из указанных тегов |

Без `page_order` сначала идут `text_pages`, затем негруппированные рецепты и группы. Новую `book_page` укажите в `page_order` явно. Значения `recipe_groups` должны также присутствовать в `recipe_pages`.

Для скрытого исследования одного списка триггеров недостаточно: штатный обработчик сканирования рассматривает `hidden: true` с непустым `aspects`. Затем действуют правила сканирования и доступа к исследованиям. API 1 не предоставляет универсальную регистрацию произвольного нового типа триггера; для собственного игрового события аддон проверяет условия на сервере и при необходимости выдаёт завершённое исследование через `ResearchApi.grant`. Это не операция «только обнаружить» скрытый узел.

Имена и текст задаются переводами. Название исследования имеет точный ключ `tc.research_name.myaddon:introduction`, включая двоеточие. Значения `text_pages` - ключи перевода старых текстов с разметкой `<BR>`, `<LINE>`, `<IMG>namespace:path:u:v:w:h:scale</IMG>`. Новые смешанные страницы используют элементы ниже; старую разметку изображений не переносите в элемент `text`.

## Смешанная страница

`data/myaddon/thaumcraft/introduction_page.json`:

```json
{
  "kind": "book_page",
  "id": "myaddon:introduction_page",
  "type": "thaumcraft:layout",
  "elements": [
    {"kind": "text", "value": "page.myaddon.intro", "width": 90},
    {"kind": "image", "value": "minecraft:textures/item/diamond.png", "x": 105, "y": 0, "width": 24, "height": 24},
    {"kind": "rule", "width": 90, "height": 9},
    {"kind": "item", "value": "minecraft:diamond", "width": 16, "height": 16, "tooltip": ["page.myaddon.tip"]},
    {"kind": "aspect", "value": "aer", "count": 5, "width": 16, "height": 16},
    {"kind": "link", "value": "myaddon:introduction"}
  ]
}
```

Для встраивания схемы добавьте элемент `{"kind":"recipe","value":"myaddon:diamond","height":160}`. Он займёт не менее 160 логических пикселей и при поточной вёрстке может перейти на следующую страницу. В данном примере рецепт уже показан отдельной страницей исследования.

| Элемент | `value` | Поведение |
| --- | --- | --- |
| `text` | Ключ перевода или текст | Перенос строк по `width`; `translate: false` отключает перевод |
| `image` | Полный путь PNG | Рисуется с размером `width × height`, умноженным на `scale` |
| `item` | ID предмета | Стандартный предмет 16×16; `count` задаёт количество |
| `aspect` | Тег аспекта | Значок 16×16 с количеством `count` |
| `recipe` | ID рецепта | Штатная схема рецепта |
| `link` | Ключ исследования | Подписанная ссылка; название берётся из `tc.research_name.<key>` |
| `rule` | Не используется | Горизонтальная линия шириной `width` |

Общие значения по умолчанию: `kind: "text"`, `value: ""`, `x: -1`, `y: -1`, `width: 139`, `height: 9`, `scale: 1`, `count: 1`, `translate: true`, `tooltip: []`. Подсказки - массив ключей перевода. Для предметов/аспектов задавайте размер области подсказки 16×16 явно.

Поле страницы - **139×199** логических пикселей. Первая страница исследования оставляет 25 пикселей под заголовок, то есть 174 под содержимое. Координаты не зависят от экранного масштаба. При `y: -1` элемент участвует в вертикальном потоке и переносится на следующую страницу; `x: -1` означает начало строки. Ручной `y` не передвигает курсор потока: автор сам оставляет место, чтобы элементы не перекрывались. Текст с ручным `y` переносится строками вниз от этой точки.

Пределы полей: `x` от -1 до 139, `y` от -1 до 199, `width` 1–139, `height` 1–199, `scale` больше 0 и не больше 4, `count` неотрицательный. Это пределы входных данных, а не автоматическая проверка всех пересечений: учитывайте `x + width`, `y + height` и размер первой страницы. `scale` меняет только изображение; предметы/аспекты остаются 16×16, текст переносится штатным шрифтом. Проверяйте длинные переводы.

Особая страница использует собственный `type`, например `myaddon:meter`, и объект `data`. Регистрация валидатора и клиентского рендерера показана в [Java API](API.ru.md#особая-страница).

## Перевод примера

`assets/myaddon/lang/ru_ru.json`:

```json
{
  "category.myaddon.workshop": "Мастерская",
  "tc.research_name.myaddon:introduction": "Первые опыты",
  "page.myaddon.intro": "Магический верстак использует вис из палочки. Здесь начинается ваша мастерская.",
  "page.myaddon.tip": "Результат первого опыта",
  "aspect.myaddon.resonance": "Резонанс"
}
```

Добавьте эквивалентный `en_us.json`; ресурсы `assets` не синхронизируются серверным датапаком, поэтому переводы и изображения должны присутствовать у клиента.

## Аспекты предметов, блоков и сущностей

Новый составной аспект сначала регистрируется в Java, как в [быстром старте](QUICKSTART.ru.md). Шесть первичных аспектов сохраняются: `aer`, `terra`, `ignis`, `aqua`, `ordo`, `perditio`. `thaumcraft:aer` распознаётся как старый `aer`; собственный аспект использует полный тег, например `myaddon:resonance`.

Назначения предметам/блокам: `data/myaddon/thaumcraft/object_aspects.json`:

```json
{
  "kind": "object_aspects",
  "entries": {
    "minecraft:diamond": {"vitreus": 4, "myaddon:resonance": 2}
  }
}
```

Это демонстрационное изменение состава существующего предмета; в своём аддоне обычно указывайте ID собственных предметов и блоков. `entity_aspects` использует такую же структуру с ID типов сущностей. Числа - целые 1–32767, не centivis. Состав `ItemStack` может дополняться штатными правилами компонентов, зелий, зачарований и наполненных ёмкостей; для чтения конечного состава используйте `AspectApi`.

Дополнительные правила загрузчика:

| `kind` | Форма значения в `entries` |
| --- | --- |
| `item_tag_aspects` | ID тега предметов → `{"aspects":{"aer":1},"required_item_tags":[]}` |
| `derived_object_aspects` | ID предмета → `{"inherit":"minecraft:diamond","add":{"aer":1},"merge":{"ordo":1},"remove":["perditio"]}` |
| `stack_aspect_minimums` | ID предмета → карта минимальных аспектов стека |
| `potion_aspect_bases` | ID зелья → карта аспектов |
| `potion_aspect_effects` | ID эффекта → карта аспектов |
| `enchantment_aspect_minimums` | ID зачарования → карта аспектов |
| `scan_groups` | ID предмета/блока → общий строковый ID группы сканирования |
| `entity_variant_aspects` | ID типа сущности → массив `{"field":"...","value":"...","aspects":{"aer":1}}` |

В `derived_object_aspects` поля необязательны; `add` добавляет количество, `merge` задаёт минимум, `remove` удаляет теги. Варианты сущностей опираются на поддерживаемые штатным обработчиком поля, а не на произвольный Java-предикат или NBT-путь. Меняя группы сканирования уже выпущенного аддона, учитывайте существующие сохранённые ключи.

## Рецепты

Минимальный рецепт из быстрого старта: `data/myaddon/recipe/diamond.json`:

```json
{
  "type": "thaumcraft:arcane",
  "research": "myaddon:introduction",
  "vis": {"aer": 5},
  "pattern": [" I ", "IDI", " I "],
  "key": {
    "I": {"item": "minecraft:iron_ingot"},
    "D": {"item": "minecraft:diamond"}
  },
  "result": {"id": "minecraft:diamond", "count": 2}
}
```

Здесь `vis.aer: 5` означает **5 вис = 500 centivis** до скидок. Это исключение совместимости формата рецепта: `RecipeDisplay.vis()` и `WandApi` используют centivis. В магическом рецепте допустимы только первичные аспекты, 1–32767 целых вис на аспект.

| `type` | Дополнительные поля |
| --- | --- |
| `thaumcraft:arcane` | `research`, `vis`, `pattern`, `key`, `result` |
| `thaumcraft:arcane_shapeless` | `research`, `vis`, `ingredients` (1–9 Ingredient), `result` |
| `thaumcraft:crucible` | `research`, `catalyst` (Ingredient), `aspects` (эссенция), `result` |
| `thaumcraft:infusion` | `research`, `input` (центральный Ingredient), `components` (1–64 Ingredient), `aspects`, `instability` (0–25), `result` |
| `thaumcraft:infernal_bonus` | `ingredient`, `result`, необязательный `base_count` (0–64, по умолчанию 0); бонус адской печи, не гарантированный обычный выход |

Ingredient может ссылаться на `item` или `tag`. `result` - формат ItemStack 1.21.1 с `id` и необязательными `count`/`components`. Эссенция в `aspects` задаётся целыми единицами 1–32767. Для тигля требуется непустая карта аспектов. Используйте существующий ключ исследования; отображение в книге или просмотрщике само по себе не разрешает крафт.

Пример инфузии с обычными предметами (для отдельного файла рецепта):

```json
{
  "type": "thaumcraft:infusion",
  "research": "myaddon:introduction",
  "input": {"item": "minecraft:iron_ingot"},
  "components": [{"item": "minecraft:diamond"}, {"item": "minecraft:quartz"}],
  "aspects": {"ordo": 8, "vitreus": 4},
  "instability": 2,
  "result": {"id": "minecraft:gold_ingot", "count": 1}
}
```

Обычные рецепты поддерживаемых типов подхватываются ядром и AOP:TC4 Compact автоматически. Java-контракты `IArcaneRecipe`, `CrucibleRecipe`, `InfusionRecipe` служат основой для собственных сериализаторов; им также нужны обычная регистрация RecipeType/RecipeSerializer и подключение к нужному игровому обработчику. Один `RecipeDisplays.register` добавляет лишь отображение, а не механику изготовления.

## Перезагрузка и совместимость

`/reload` заново читает контент из `data/`, проверяет ссылки, типы страниц, коллизии и циклы родителей. Успешный каталог синхронизируется клиентам. При ошибке этого каталога сохраняется предыдущий рабочий снимок; это не обещание отката всех независимых загрузчиков Minecraft и других модов. Ошибка первой загрузки не создаёт корректный каталог автоматически.

Чтобы изменить определение датапаком, перекройте **тот же путь ресурса** пакетом более высокого приоритета. Два разных файла с одним ID категории/страницы/исследования вызывают коллизию. JSON не перекрывает Java-регистрацию книги с тем же ID: Java-значения являются исходными определениями, а не запасным вариантом при дубликате. Назначения аспектов имеют отдельные правила слияния: повторный ключ `entries` заменяет соответствующую карту в порядке загрузки файлов, а не суммирует её.

Сохраняйте ключи исследований, аспектов, материалов и числовые ID улучшений между выпусками. Удаление определения исследования не стирает его ключ из сохранённых знаний. Изменение ID не является миграцией прогресса. Бинарные аддоны 1.7.10 не загружаются автоматически; их Java, регистрацию, рецепты и сохранения нужно адаптировать.
