Ядро 1.0.0, NeoForge 21.1.252, Java 21. API уже находится внутри основного мода. **Не кладите API JAR в mods**: он нужен только как compileOnly-зависимость при разработке. Бинарные аддоны Forge 1.7.10 нужно портировать.

## Подключение

Распакуйте SDK, откройте example-addon и выполните `./gradlew.ps1 build`. Нужна Java 21 через JAVA_HOME или PATH. Результат: build/libs/thaumcraft-example-1.0.0.jar. Пример компилируется против ../lib/thaumcraft-api-1.0.0.jar, Minecraft и NeoForge; внутренние классы ядра в classpath не включены. Sources JAR помогает переходить к исходникам API в IDE. Сохраняйте структуру SDK либо измените путь compileOnly files(...).

Для игры установите ядро, его обычные зависимости (включая Curios) и свой аддон. Демонстрационный мод устанавливается отдельно и предназначен для тестового экземпляра. Не включайте API, Minecraft, JEI или EMI внутрь своего JAR. Идентификаторы вашего пространства имён должны сохраняться между версиями.

## Регистрация и стороны

Из конструктора мода подпишитесь через `AddonRegistrationEvent.BUS.addListener(...)`. Эта отдельная публичная шина активна во время common setup; игровая `NeoForge.EVENT_BUS` в этот момент выключена и не доставляет событие. Событие вызывается один раз в очереди common setup после регистрации родных материалов палочек, до загрузки моделей клиента и данных сервера. В нём регистрируются составные аспекты, категории книги, Java-исследования и страницы, валидаторы PageTypes, стержни, наконечники, обработчики набалдашников, улучшения и поставщики отображений рецептов. Коллизии вызывают ошибку; регистрация содержимого книги после события закрывается. Сами предметы, блоки и BE регистрируются обычным DeferredRegister на шине мода. События CatalogChangedEvent и KnowledgeChangedEvent по-прежнему находятся на NeoForge.EVENT_BUS.

thaumcraft.api.client содержит только клиентские контракты. BookRenderers регистрируются в клиентском setup через подписчик Dist.CLIENT. Общие классы устройства не должны импортировать клиентские рендереры. Идентификаторы моделей FocusBehaviors/WandVisuals можно регистрировать с общей стороны: ядро подключает их к обычной загрузке ресурсов.

ResearchApi.knowledge(serverPlayer) возвращает копию знаний. ResearchApi.grant(serverPlayer,key) выполняет настоящую сохраняемую транзакцию с обычными последствиями изучения; требуется серверный поток. definitions(), books(), clientKnowledge() — согласованные клиентские снимки. Не используйте их для разрешения серверных действий.

На отдельной AddonRegistrationEvent.BUS проходит начальная регистрация. На игровой шине NeoForge.EVENT_BUS доступны CatalogChangedEvent и KnowledgeChangedEvent. У них есть признак client(); серверное событие каталога также содержит server(). События каталога служат сигналом сброса кешей; revision не является сохраняемым глобальным номером. Знания в событии выдаются копией.

## JSON, /reload и старые данные

Размещайте файлы в data/<namespace>/thaumcraft/**/*.json. Они загружаются как ресурсы датапака и синхронизируются с клиентами после /reload. Ресурс более высокого приоритета заменяет файл с тем же путём. Одинаковые ID в разных файлах запрещены. Java-регистрации и JSON должны иметь разные ID; изменение Java требует перезапуска, JSON — только /reload.

Перед установкой нового каталога проверяются синтаксис, категории, родители, соседи, циклы, требования страниц, типы страниц, ссылки и аспекты. Ошибка отменяет перезагрузку целиком: предыдущий рабочий каталог и прогресс остаются. При первом запуске ошибочный аддон вызывает ошибку загрузки. Удаление определения не удаляет сохранённый ключ изучения; возвращение определения снова связывает его с прежним прогрессом.

Старые ключи GOGGLES, ROD_greatwood, FOCUSFIRE, латинские теги аспектов, материалы палочек и номера улучшений 0–20 сохраняются. thaumcraft:aer является алиасом aer. Новые исследования, вкладки, страницы и аспекты используют ваш namespace. Имена исследований: tc.research_name.<id>; имя категории — переданный ключ локализации.

Рабочие JSON и Java приведены в example-addon. Полная схема с короткими JSON-примерами также находится в README.en.md:

- book_category: id, name, icon (полный путь текстуры), order, необязательные background и required_research.
- research: key, category, parents, aspects, complexity, auto_unlock, concealed, column/row, text_pages, recipe_pages, page_order, icon; поддерживаются прежние флаги, скрытые родители, триггеры, warp, secondary и recipe_groups.
- book_page: id, type (по умолчанию thaumcraft:layout), elements либо data для особого типа.

Страница имеет логические размеры 139 × 199; применяются существующее масштабирование и подгонка книги. Без x/y (либо -1) элементы идут потоком; текст переносится по ширине и продолжается на следующих страницах. Явный y задаёт ручную верстку, которая должна помещаться на страницу. На первой странице учитывается заголовок.

Элементы: text, image, item, aspect, recipe, link, rule. text.value по умолчанию является ключом перевода; translate:false задаёт буквальный текст. У image указываются ресурс текстуры, width/height и необязательный scale. У item — ID предмета, у aspect — тег и count, у recipe — ID рецепта, у link — ID исследования. Tooltip — список ключей перевода. Ссылки открывают изученное исследование либо центрируют его категорию, если оно ещё закрыто. Прежняя разметка встроенных исследований сохраняется.

Для особой страницы зарегистрируйте PageTypes.register(id,validator) с общей стороны и BookRenderers.register(type,renderer) с клиентской. JSON передаёт type и data. BookRenderContext предоставляет GuiGraphics, Font, начало страницы, отрисовку предметов/аспектов/рецептов, ссылки и подсказки. Координаты мыши в обработчиках локальны странице. В примере есть Java-страница с индикатором.

## Аспекты, эссенция и вис

Aspect.registerCompound(id,color,icon,translationKey,first,second) создаёт составной аспект с собственной иконкой. Регистрируйте одинаковое определение на клиенте и сервере; первичных аспектов остаётся шесть. AspectApi.aspects(...) возвращает копию состава предмета, блока или сущности с учётом правил. AspectApi.scanned(stack) проверяет сканирование текущим клиентом.

Назначение состава через JSON: kind object_aspects или entity_aspects, поле entries со словарём registry ID → {aspect: amount}. Для блоков подходят ID их предметов. Существуют также item_tag_aspects, entity_variant_aspects, derived_object_aspects, stack_aspect_minimums и scan_groups. Количества положительные, теги аспектов могут быть namespaced.

Рецепты 1.21 лежат в data/<namespace>/recipe/*.json: thaumcraft:arcane, arcane_shapeless, crucible, infusion и существующие динамические/адские сериализаторы. Стандартные рецепты аддонов автоматически появляются в общем каталоге. Для Java доступны IArcaneRecipe, CrucibleRecipe и InfusionRecipe. Выход ItemStack задаётся через {"id":"yourmod:device","count":1}.

RecipeDisplays.register(id,provider) добавляет отображения особого типа рецептов. RecipeDisplay содержит уникальный ID варианта, ID настоящего рецепта, тип, исследования, ингредиенты, результаты, вход/выход аспектов, centivis, нестабильность, уровни опыта, устройства и примечания. ID разных динамических вариантов должны различаться. Результат кешируется по Level и сбрасывается при обновлении каталога; при изменениях собственного каталога вызовите invalidate(). Сервер получает рецепт из своего поставщика, а не из переданного клиентом списка предметов.

Эссенция измеряется целыми единицами. IAspectContainer.addToContainer возвращает НЕПРИНЯТЫЙ остаток; IEssentiaTransport.addEssentia — ПРИНЯТОЕ количество. Устройство выставляет EssentiaCapabilities.CONTAINER и TRANSPORT в RegisterCapabilitiesEvent. Учитывайте стороны, suction и серверный поток. EssentiaStore предоставляет ограниченное хранилище; сохраняйте его содержимое и вызывайте setChanged после изменений.

Вис хранится в centivis: **100 centivis = 1 вис**. Ёмкость WandRod и цены vis в родном arcane JSON по совместимости остаются целыми вис. WandApi.centivis выполняет явный проверяемый перевод. stored/capacity/set/quote/consume работают с centivis; consume(...,false) проверяет, true списывает в серверном потоке. Сохраняются модификаторы наконечников, брони и frugal. Перенос в сетку не списывает вис.

TileVisNode подходит для ретранслятора/источника. Его жизненный цикл исключает выгруженные чанки из сети. Источник переопределяет consumeVis и выдаёт фактически доступное количество. Потребитель может вызвать VisNetHandler.drainVis(level,pos,primal,centivis). Допустима частичная выдача; чанки принудительно не загружаются; эти операции не являются атомарной оплатой нескольких аспектов сразу. Собственные запасы сохраняет аддон; в save/load вызывается super. Пример хранит ограниченный заряд и не создаёт бесконечный вис.

## Палочки и набалдашники

Namespaced-конструкторы WandRod/WandCap принимают ID, исследование, предмет компонента, ёмкость/цену/модификаторы. Эти параметры работают в настоящей сборке палочки и применении магии. WandApi.parts записывает существующие компоненты данных. Для вида в руке и инвентаре задайте WandVisuals.register(kind,parts,modelId) на каждую поддерживаемую комбинацию. Без модели используется обычный вид палочки. Пример содержит модель составной палочки. Прикреплённая головка центрируется по x/z=8, y≈18..22; ядро добавляет смещение для посоха.

Набалдашник наследует ItemFocusBasic; FocusBehaviors связывает предмет с обработчиком и моделью на палочке. begin/cast/end работают на сервере. Для непрерывного применения вызываются попытки cast по тикам с ограничением getActivationCooldown в МИЛЛИСЕКУНДАХ, как у родных набалдашников. Перед cast ядро резервирует цену со скидками; true оставляет списание, false/исключение возвращает резерв. Не списывайте ту же цену повторно и не меняйте материалы палочки внутри callback. Конец применения обрабатывается также при отпускании и выходе игрока.

FocusUpgradeType.register использует стабильный целочисленный ID в сохранениях и namespaced-ключ. В примере ID 24000; для своего аддона выберите и документируйте постоянный свободный номер. Повтор ID или имени вызывает ошибку. Перегрузка с ResourceLocation принимает отдельный ресурс иконки, в том числе текстуру зависимости. getPossibleUpgradesByRank/canApplyUpgrade подключены к настоящему манипулятору. Сохраняйте остальные компоненты ItemStack при изменении предмета.

## Отдельная интеграция JEI/EMI

aoptc4-client-compact-0.8.0.jar — необязательный клиентский мод для обновлённого ядра. Он не содержит и не устанавливает просмотрщики. Диапазоны для Minecraft 1.21.1: **JEI от 19.8.4.110 до 20 (не включая 20)**, **EMI от 1.1.13 до 1.2 (не включая 1.2)**. Сборка использует минимальные поддерживаемые API; запуск не привязан к одному билду. NEI для этой цели заменён JEI/EMI. Если есть оба, работает родной адаптер EMI; JEI ничего не регистрирует в мост повторно.

Каталог показывает магический крафт, тигель, варианты инфузии (зачарование/рунное усиление), случайные бонусы адской печи, перегонку, разложение и кристаллизацию эссенции. Каждый аспект имеет одну запись для поиска рецептов и применений вис/эссенции; количества и единицы сохраняются в слотах рецептов. Состав предмета отображается выходами перегонки с учётом сканирования. Требования исследований ведут в настоящую серверную книгу; книга должна находиться в инвентаре. Варианты динамической инфузии являются примерами: дополнительные зачарования реального предмета могут менять цену. Адский бонус не объявляется гарантированным выходом.

Настройки thaumcraft_viewers-client.toml доступны и через экран настроек мода:

- recipes: ALL_WITH_REQUIREMENTS по умолчанию либо RESEARCHED_ONLY.
- aspects: SCANNED_ONLY по умолчанию либо ALL.

Изучение/сканирование обновляет фильтры с короткой задержкой. JEI использует runtime API. В EMI 1.1.x нет публичного метода сброса каталога, поэтому изолированный адаптер вызывает EmiReloadManager.reload через reflection-мост. При несовместимой замене EMI ошибка явно записывается в журнал. /reload также очищает кеш рецептов ядра.

WorkbenchApi выдаёт Class и MenuType настоящего меню без импорта внутреннего класса; JEI подбирает обработчик по точному классу.

Кнопка «+» передаёт только menu ID, state ID, ID варианта и намерение количества. Сервер проверяет открытое меню, рецепт, знания, ингредиенты и место, планирует изменения на копиях и лишь затем применяет их. Содержимое прежней сетки возвращается или используется без выбрасывания. При ошибке ничего не меняется. Перенос только заполняет сетку: не крафтит, не создаёт результат и не расходует вис. Запросы EMI на автоматический крафт в курсор/инвентарь не поддерживаются.


### Открытие аспектов и родная верстка рецептов

Семь категорий используют графику книги: сетку магического крафта, центральный предмет инфузии с компонентами по кругу, символ тигля, количества аспектов, нестабильность и значки исследований. Одинаковые компоненты инфузии объединяются с указанием количества. Наведение на исследование показывает переведённое название, категорию и родителей; клик открывает книгу. Устройство регистрируется один раз на категорию, поэтому слева в JEI нет сотен повторяющихся блоков.

В обоих просмотрщиках есть список аспектов, сочетания и страницы источников. Неизвестный аспект отображается как `?`, его название, состав и источники скрыты. Шесть первичных аспектов известны изначально. Открытый аспект остаётся известным при нулевом запасе очков. Вис и эссенция используют одну запись списка и один поиск, но в рецептах сохраняются разные количества и единицы.

При наведении на открытый аспект видны его компоненты (неизвестные скрыты), до пяти отсканированных источников и выход эссенции. Стандартные кнопки рецептов/применений просмотрщика открывают сочетания, полные страницы источников или рецепты с расходом аспекта. Страницы источников всегда требуют сканирования: несканированные предметы, включая предметы блоков, не показываются даже при настройке состава ALL. После сканирования или открытия аспекта названия, страницы и поиск обновляются без переподключения.

Поведение и расположение ритуалов ориентируются на [GTNH Aspect Recipe Index](https://github.com/GTNewHorizons/AspectRecipeIndex). Код и ресурсы GTNH не копируются; используются существующие изображения книги Thaumcraft.

## Проверки

CHECKLIST.ru.md содержит сценарии самостоятельной игровой проверки. Автоматика проверяет старые правила, регистрацию, ссылки/коллизии, копии каталога, сохранение ключей прогресса, единицы, 2000 случайных переносов и связывание классов в четырёх сочетаниях просмотрщиков. Аудит JAR проверяет отсутствие внутренних зависимостей у аддонов и вложенных классов API/просмотрщиков. Minecraft при этом не запускается; связывание классов не является игровой проверкой.

### Проверка диапазона совместимости

Команда `./gradlew.ps1 check -PviewerCompatibility=minimum`, затем значения `middle` и `latest`, проверяет ранние, промежуточные и актуальные версии. Каждый профиль проверяет отсутствие просмотрщиков, JEI отдельно, EMI отдельно и оба вместе. Проверяются реальные вызываемые методы/поля API, реализация обязательных методов интерфейсов, сброс каталога EMI и настоящий Maven-разбор диапазонов версий, включая JEI 19.64.0.455 и суффиксы сборок EMI. Minecraft не запускается.

Проверенные профили: JEI 19.8.4.110 / 19.19.6.233 / 19.64.0.455; EMI 1.1.13 / 1.1.20 / 1.1.24 для Minecraft 1.21.1. Это проверка API и связывания классов; она не означает игровую проверку каждого выпуска диапазона.

### AOP:TC4 Compact 0.8.0

Имя в списке модов: AOP:TC4 Compact. Сохраняется прежний mod ID thaumcraft_viewers. Ядро/API 1.0.0 добавляет AspectApi.variants() для получения копий наполненных флаконов, банок, кристаллов и сгустков. JEI регистрирует компоненты как подтипы и включает все 240 родных вариантов.

Схемы и области наведения/нажатия подгоняются под доступную высоту: EMI может ограничивать карточку до 125 логических пикселей при GUI ×4. Текст на светлой карточке рисуется без тени; статусы рисуются крупными цветными символами справа от значка. Большие количества сокращаются на значке (524k, 2.1G), точное значение остаётся в подсказке. Название аспекта, количество и служебные строки подсказки различаются цветом.

ResearchNavigation.resolve(...) — общий чистый резолвер: изученное открывает страницу, доступное центрирует и подсвечивает узел, при недостающих родителях выбирается ближайший доступный предок. Закрытый триггером узел не раскрывается; выводится сообщение об исследовании мира и книги. Открытие по-прежнему проверяется сервером и требует книгу.
